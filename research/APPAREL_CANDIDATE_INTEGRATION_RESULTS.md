# 服装候选检索接入：102 条工具查询与 8 次 Agent 开发试跑

2026-09-09。**来源限定的候选检索已接入可选 Agent 版本，开发验收通过。** 在已知服装目录中，Any 关键词匹配消除了本轮 32 次空检索；真实生成模型的两组各 4 次试跑都完成预定操作。Any 组少用了 4 次模型调用，但样本不足以证明稳定的质量、费用或速度优势。当前工作台默认版本尚未切换。

## 做了什么

`candidate_search.py` 先把检索范围限定为已有来源记录的 37 个服装变体，再筛选明确的品牌、颜色、尺码和款式。随后执行词项匹配、候选截取和已有 Qwen3-Reranker-0.6B 重排。零候选与单候选分别明确记录；多候选才调用 GPU。重排输出的成员集合不合法时，保留明确的回退记录。

All 要求全部检索词出现，Any 允许部分词命中；二者均保留结构化条件。空查询表示在满足条件的商家变体中浏览，不调用模型。搜索本身只读；读取来源、选入候选、核验订单、提出方案和用户确认仍是各自独立的操作。

`CandidateSearchAgent` 继承原 v3 状态契约，仅替换候选搜索入口。本次没有增加同义词词典、Embedding 训练或新生成模型。37 个变体来自公开商品文本；库存、品牌区域规则、价格、重量和研究款式分组等继续明确标注为模拟数据。

## 第一部分：固定查询下检查工具接入

34 个不同品牌／颜色／尺码组合，每组使用 3 条开发模板：`cotton t-shirt`、`shirt cotton`、`cotton tee`。合计 **102 条查询 × 2 种方法 = 204 次工具执行**。不是 102 笔真实订单，也不是 102 个独立自然语言样本。预期 SKU 集合只供评分使用，不传入搜索工具。

前两个模板，两组均为 34/34；`cotton tee` 模板，All 为 2/34，Any 为 34/34。**Any 的改善来自命中 `cotton` 并放过未命中的 `tee`，不表示学会了 tee 与 T-shirt 的同义关系。** 当前结构化条件与已知目录承担了大部分候选正确性约束。

五种状态分别为正常可继续、库存为零、单位缺失、区域不允许，以及请求尺码与候选不同。预期结果包括 `ready`、`needs_clarification` 和 `unfulfillable`；“检查通过”表示正确识别状态，不表示所有订单都能履约。860 次已执行状态检查是确定性程序运行，不计为 860 次自主 Agent 成功。

本段没有付费或生成模型调用。耗时来自一次顺序运行，部分短调用受计时分辨率影响；Any 的 P95 反而较高，不能宣称稳定加速。

验收同时检查实际选入 SKU、报告与状态一致、来源读取、原始需求保留、提案存在性、证据字段和没有擅自批准替代／确认。事后另从保存的 SQLite 核对选入状态、未改库存和待确认提案；使用独立的起订量及整包数量算术核对四例结果。

All 的后 3 例第一次 `cotton tee` 检索为空，随后清空查询、保留结构化条件进行目录浏览后恢复。Any 的浅蓝订单使用了 `t shirt`，因此这一部分的模型生成查询不完全相同。两组都成功，不能把调用差异全部归因于匹配算子。完整空检索和恢复轨迹都保留。

AIHubMix 请求模型为 `gpt-5.6-luna`，返回别名为 `gpt-56-luna`；40 次调用均为成功，别名差异留在记录中，未独立确认服务端权重身份。输出 token 中的推理部分按接口报告保留（All 381、Any 323），不额外重复累计费用。本轮没有流式首 token／末 token 时间，不能拆分“思考秒数”与“回答秒数”；表中是端到端墙钟时间。

本段另有 2 次 GPU 重排请求、4 对商品。本轮两部分合计 **17 次 GPU 请求、34 对商品**，不把请求数称为底层前向次数。8 次 Agent 运行的新增费用为 **¥0.291625**；全项目账本从 ¥313.566736 增至 **¥313.858361／¥480**，增加 40 条至 16,896 条。金额是本地 token 价卡的保守估算，不是服务商已出账发票。此前 100 模型选择任务的独立 ¥100 上限及 ¥64.986070 记录没有变化。

## 可以支持的结论与后续门槛

现在可以说明：完成了“公开来源变体限定检索—程序核验—实际 Agent 操作—逐例轨迹与费用核对”的开发闭环。可以进入更广的订单验证。不能把 102/102 写成开放商品检索准确率或新 NDCG，也不能把它与此前 200 条全目录查询的 48.12% 已标注精确覆盖直接相减；检索范围和标签分母不同。

当前不据此切换默认版本。下一步应在冻结业务条件下覆盖无对应商品、模糊描述、多个冲突条件、缺货替代、批量订单和运输修订，并固定三种编排方式的模型与工具能力。若提出新方案，应另建协议与证据版本，保留原失败，避免在相同开发样本上反复挑最好的一次。没有新增真实客户、销售额或实际物流履约。

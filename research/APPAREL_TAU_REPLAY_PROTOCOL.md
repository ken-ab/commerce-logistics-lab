# 服装提案的外部工具回放协议

2026-09-09；对既有 144 次 v5/v6 运行进行事后验证，不新增模型实验。

## 范围与独立性

使用本地已安装、未修改的 Sierra `tau2-bench`，固定提交 `672227c6b6676edc20d57ea53b7000262aae77b9` 的 `EnvironmentEvaluator.calculate_reward(strict_replay=True)`。这是自定义服装业务环境，不能当作官方 retail/airline/telecom 的分数或排行榜成绩。适配器代码、上游关键文件、初始库、旧记录和新结果均保存哈希。

每条记录从已登记的初始 SQLite 数据库建立两份隔离副本。预测环境按记录顺序重新执行所有 `kind=tool` 操作，包括启动读取、专家操作和返回业务错误的操作；不重复执行委派父调用。使用该记录原来的 v5/v6 类、规则、资料和模拟时间。调用 `observed()` 而非返回保存的答案，以重建读过旧提案等会影响后续写入的内存状态。

上游默认跳过不修改状态的读取操作。因此适配器统一提供 `apparel_operation(name, arguments, actor)`，标记 `mutates_state=True`：这些调用会更新 Agent 的观察记录，而且其读取结果也必须参与严格比较。实际八种业务工具的名称、原始参数和角色仍保留在参数内，并使用原 Pydantic 模式核验。未知名称提前拒绝，避免上游将未知工具当作无操作跳过。

## 三个分别报告的检查

1. **工具返回复现**：上游重做工具调用并比较记录中的 observation_id、tool、success 和完整 result；再补一项原生类型的规范 JSON 比较。固定上游版本将数值和布尔值序列化为字符串，因此单靠上游检查不能区分数值 `2` 与字符串 `"2"`。不把模型文字、目录提示、工具耗时、运行标识或审计时间戳当作业务返回值。
2. **持久状态复现**：将预测环境与该次运行保存的真实 SQLite 比较。包含 metadata、inventory、drafts、approvals、proposals、transport_events、confirmations 的所有行和字段，解析 JSON 列；只排除 traces 表。保留库存与规则版本、所有提案版本、前后引用、批准、确认、成本、运输时刻和日期。此项保持真实对象 ID，不做匿名化。
3. **目标数据库一致**：上游独立建立参考环境，只根据已登记案例的 expected.proposal 生成参考动作。`revise/infeasible` 读取初始目标提案并生成一次修订；`keep/none` 保持原库。不从模型结果、执行轨迹或最终快照推导参考动作。目标比较仅将提案的不透明随机 ID 一致映射为“所属订单 + 版本”，保留引用关系；其余字段不删。该目标是固定确定性规划器的结果，不代表全局最优运输路线。

工具复现、数据库达标和原有严格任务验收是不同指标。即使一个未成功提交最终回答的运行已形成正确业务状态，仍保留原始失败结果；本验证不重算或覆盖原研究的成功率。

## 非确定性、无网络与失败

初始对象 ID 直接来自冻结初始库。预测回放仅在真实 `prepare_proposal` 调用内部，为 UUID 工厂提供该次创建记录的合法、新鲜提案 UUID；不得复用已有对象 ID。同一个 ID 的后续引用仍按原值处理。此控制不提供路线、规则、库存、状态或工具结果。参考环境使用独立确定性 UUID；固定模拟时刻由原案例提供。生产文件与上游文件不作修改。

客户端和候选重排器使用拒绝调用的哨兵，并在执行阶段禁止 socket 连接。144 次原运行没有候选检索调用，因此本次无需 GPU、外部接口或模型费。若未来记录需要重排器，不得偷用保存的排序冒充重跑；应另立包含该依赖的协议。

完整运行前使用小规模测试和反例，至少覆盖：被篡改的只读/写入结果、记录中合法保留的错误、错误提案 ID、未记录的库存写入、遗漏写入、重复创建 ID、前后版本引用被篡改，以及额外读取仍达到相同目标。保留失败，不通过删除字段、放宽 strict 或反复运行模型来修复成绩。

## 交付

每次运行输出上游 task、重放轨迹、三份业务状态快照、逐步返回摘要及 τ 奖励；汇总 6 个条件的三种验证计数，并并列原严格验收。另保存失败与反例、无新增模型调用/费用账本核对、文件完整性记录。正式运行的输出目录只创建一次；中断或失败目录保留以供检查。

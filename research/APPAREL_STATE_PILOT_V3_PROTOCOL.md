# 订单状态与动作检查 v3：开发试跑协议

本轮在查阅原324条最终轨迹及54次字段目录开发结果后设计。12个新写场景使用已知开发商品、现有业务规则与已知任务类型，不是未见商品或独立最终测试；所有144个结果都报告，失败不重试，不据此替换工作台默认。

## 问题与对照

在相同调用者操作下，起始状态读取是否减少错误订单/提案身份和重复澄清？动作与结束检查能否减少未实际操作、过期状态或必要依据缺失？三种原执行策略的代价和结果如何变化？

四种条件：`neither`关闭两项；`bootstrap`只开起始读取；`guard`只开检查；`both`都开。每种分别采用`single / coordinator / on_demand`。所有条件共同使用v3操作提示、逐行选择快照、字段目录v2、同一Luna模型与原业务工具；`neither`是新的共同基线，不能当作历史v1/v2。

调用者操作仅为查商品、核验订单、选入候选、准备或复核提案，并携带用户指定SKU/字段/行/提案选择器。研究侧案例ID、类型、期望状态、正确候选、答案和评分代码不进入模型；业务来源标识使用不含场景语义的散列ID。相同任务在12个配置中克隆同一初始数据库、商品世界、事件和时钟。

起始读取是真实`read_order`工具观察，计入共同32次业务工具上限，另列host read；根协调员同样获得该观察但不因此获得直接业务工具权限。检查关闭时也记录末次候选检查结果，但不反馈错误、不修复模型操作。检查开启时必要修复使用同一12次总模型调用、每专家最多4次上限。专家局部报告不承担根执行者完整操作。调用上限、token配置、无自动重试、计费由原冻结运行时提供。

## 案例与独立预检查

12个开发场景：颜色资料、无运输准备、缺少数量单位、销售区域阻断、缺货替代选入、正常运输、1分钱预算无解、班次取消修订、已批准替代加取消修订、已批准替代只读核验、无关事件下保留旧版、两行候选互换后纠正并准备。

预期选择及变化最少候选由研究侧独立枚举，运行器不读取。1分钱无解有出仓运输段最小固定费用大于预算的直接界限。每个初始环境在另一个免费克隆中执行已知合法操作，检查具体问题、选择行、批准不变、旧版有效性、新版状态与独立路线校验。此预检查只证明场景可运行，不是模型表现。

正式调度前保存案例、初始库/世界/seed、预检查、方法源码/协议/测试证据和原冻结方法SHA。固定随机种子26090831打乱144次组合，最多3个worker，原成本账本与480元总上限生效。预计新增约5至10元，以实际调用及未结算预留计数为准；不动100模型子任务预算或结果。遇到计费拒绝按失败记录，不能清零预留扩大预算。

每个逻辑运行在调用前创建唯一attempt文件，先落盘execution再评分；已开始未完成的运行不得自动重启。只允许恢复未开始的组合，错误/中断现场保留。不得观察部分成绩后改提示、检查、案例、工具、期望或评分。

## 评分及报告

主开发完成指标：冻结v1业务评分及已登记的语义补充口径，加本轮预先登记的逐行期望选择核验、报告逐行选择必须等于实际选择、报告SKU集合必须等于实际集合（商品资料操作除外）。新增字段核验单列原因；旧严格及补充分数仍保存。此评分从研究侧期望、业务状态和原始引用计算，不以运行时`operation_check.passed`作为正确答案或分数。

并列报告：完成数/率、业务正确、约束违规、必要来源覆盖、失败原因、API失败、调用上限、模型/业务/host读取/检查/专家调用数、输入/输出/推理token、总费用及每次平均费用、全程平均/P50/P95耗时、检查拒绝与引用修复。保留未通过完整检查的控制组结果，不能把“模型有输出”当作正确。

四配置和三策略共12行结果表，按12个场景配对；起始读取主效应为有/无读取的平均差，检查主效应同理，交互为差中之差。报告配对完成率、平均费用与时延的描述性差异；以场景为单位对12个完整配置联合自助抽样，固定种子26090832、5000次，给出区间并标注小开发样本及多比较限制。不能把3策略×12场景的36运行当作36个独立业务场景。

逐例复核四因素条件的新增完成和退步，以及检查开启后仍失败的案例。特别关注误拒绝有效提案、合法无解/澄清、父对象引用、原SKU与获批SKU的合理比较、专家局部结果。自动评分不证明每一句自由理由，也不证明真实商家收益；客户/用户仍0。

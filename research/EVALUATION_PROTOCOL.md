# 评测协议草案 v1

状态：数据分区已经固定，方法与最终评测计划尚未冻结。现有英文和中文成功运行均为开发演示，不是最终测试成绩。

## 三种不同的结果

1. **公开商品检索/排序**：使用 Amazon ESCI 人工标注。Task 1 只使用 small_version 对应的候选列表，按官方 E/S/C/I 增益及 nDCG 定义复核后实施。遍历完整目录的检索结果若包含未标注商品，不得将未标注项当作已知负例；该实验单列已标注 Exact 命中、覆盖率及未标注比例，不冒称官方 Task 1 分数。
2. **Agent 业务任务**：每例有明确用户请求、初始状态和独立预期。检查购物车、库存、运费、时限、禁用线路、订单确认边界与会话所有权。一次回复、JSON 合法或工具调用成功均不能替代任务完成。
3. **最终报告**：数字与产品属性逐项对照工具证据；订单/支付状态对照数据库。主观完整性另由经过校准的评判模型检查，保留评判原文、输入证据、指标定义和不一致例。模型评判不能覆盖确定性事实校验失败，也不能自行创造正确答案。

## 隔离与迭代

`esci_split_manifest.parquet` 保留全部官方 test；移除训练侧 1 个重叠查询的 3 条数据；剩余查询按带版本 salt 的 SHA-256 分到开发或验证。英文、日文、西班牙文分别报告，当前目录分词实现不能被假设为三种语言都有效。相同查询归组，禁止把同一查询不同商品对分散到不同区。

开发集用于失败归因、代码修复和技能候选生成。验证集只用于事先规定的晋级门禁；记录候选尝试次数，避免反复窥视。方法、提示、模型、工具 schema、评分、预算及数据版本全部固定后，再创建最终实验 manifest 并首次跑 test。最终失败保留，不因成绩不满意改同批测试的答案。

自定义业务任务也按商品/任务组隔离。相同模板生成的变体报告为模板变体，不伪装成大量独立真实客户需求。预先登记任务、重复次数和停止规则；连接失败、超时、上下文截断及循环上限均进入分母。

## 对照与自进化

先比较固定策略与至少一个简化基线，再加入从开发失败中生成的候选策略。候选只允许修改检索/排序/上下文策略，不得修改库存、确认、预算或评分规则。新版本先通过确定性回归检查和隔离验证，优于基线才启用；未达标的候选拒绝或回滚并保留记录。

报告包含任务成功率、约束违规率、事实不一致率、拒答/澄清正确率、调用次数、延迟分布、估算费用及失败请求预留。多模型比较同时保留模型身份和网络失败，不静默改模型补全结果。候选提升使用按查询/任务配对的差异与区间，不使用“两个独立置信区间重叠所以没有差异”的捷径。

## 外部工具的作用

τ-bench 源码已固定并安装，当前尚无外部评分结果。其 ENV 评分通过重放实际轨迹比较最终状态；参考动作主要用于构建正确终态，不能强制唯一工具路径。COMMUNICATE、自然语言断言与数据库得分分别解释。全部外部框架内的 Agent、用户模拟器与评判请求也必须接到统一预算账本，禁止默认 CLI 绕过账本调用模型。

本项目定制的跨境物流环境与任务只报告为“使用框架评估的定制基准”。只有协议兼容且实际运行官方任务，才可单独报告对应官方任务成绩；不能把定制任务分数换成官方排行榜结论。

## 规模与可复现性

全量目录为 1,814,924 条，原始标注为 2,621,288 条。这些是公开数据规模，不是本产品用户。真实付费客户、真实活跃用户目前均无记录；模拟会话、评测任务和负载并发单独统计。

保存数据/分区 SHA-256、上游 Git 提交、Python 与依赖版本、每例原始 trace、状态前后快照、各项评分、所有失败、技能版本和费用账本。大规模离线检索/状态测试可以不消耗 API；真实模型评测量由预估单例成本和剩余预算确定，不能靠合成调用结果补足数字。

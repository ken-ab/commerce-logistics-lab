# 账户拒绝后的恢复与进程停机保护

2026年9月8日，在最终复制实验暂停后新增操作层保护。引入时已保存52条完整trial、2条开始后的现场，266条尚未开始；这不是原最终方法冻结前已存在的组件，交付时应披露其引入时间。

原Qwen审核服务连续返回HTTP 400账户拒绝，导致完整记录中的28项审核失败。账户与访问授权问题需要恢复原服务，不能通过换端点、换审核模型或重复生成失败结果来绕过。此前的失败、费用预留和原第二版验收失败均保留。

`resume_replication.py`在当前评测Python进程内运行原`audit_replication.run --partition test --resume`。它额外启动一个守护线程，每0.5秒读取新产生的审核传输记录；只有新的、来自原DashScope主机的HTTP 400、401、402、403、404、405、410或422才触发停机。200及原客户端允许重试的429、500、502、503、504不触发这一规则。不读取报告分数来决定是否停止。

停机前写入`evidence/replication_service_pauses/`中的单独记录，再结束自身进程。它不按PID猜测或终止其他程序，不修改原评测程序、提示、费用上限、案例顺序、重试次数或评分。检测存在最多一个轮询间隔的延迟，其他在途调用可能已开始，因此不保证零额外拒绝请求。观察器自身失败也会停止，避免付费任务在失去保护时继续运行。

原CLI的中断恢复规则继续有效：完整结果不重算；已开始的逻辑任务不重新生成，已完成组件保留、缺失组件计为失败。停止不会把保留的预留费用清零，也不把未完成运行宣称为正常结束。守护记录是操作证据，不是新的业务评分。

先由用户恢复原Qwen服务，再使用以下入口。确认参数只表示调用者已经确认恢复，不是服务健康测试；本项目不会因为时间经过就自动推定账户恢复。

```powershell
$env:LOGURU_LEVEL = 'ERROR'
.\.venv-tau\Scripts\python.exe -X utf8 resume_replication.py --acknowledge-provider-restored
```

不产生模型调用的本地核查命令：

```powershell
.\.venv-tau\Scripts\python.exe -X utf8 resume_replication.py --dry-run
```

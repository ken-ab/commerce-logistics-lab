# ADR 0004：供应商账户错误停止后续调用

日期：2026-09-08。状态：已实现于服装工作台与新订单复核外层；不追溯修改冻结实验。

## 问题

原v3批量驱动预先提交144任务，首次AIHubMix余额403后仍继续开始队列中的独立任务，最终28次请求被拒绝。原始错误、结果和未知预留已经保留。需要阻止同类后续发送，同时避免暂停不相关的本地GPU和其他供应商。

## 决策

增加独立GuardedChatClient，在原预算客户端预留和发送前查询SQLite中的供应商暂停状态。明确HTTP401认证错误、HTTP402付款要求及含余额不足的HTTP403触发持久暂停。泛化的模型权限403、繁忙429与普通超时不会被当作账户欠费。保存分类原因和时间，不保存认证信息或完整响应正文。

未来研究按场景分组、有界提交最多3任务；每次开始任务和每个模型调用都检查暂停。已发送请求可正常归档，未开始任务保持未测试，暂停后没有隐式重试。恢复仅由用户报告服务已恢复后在本地显式确认；一次另记的小额探测已完成。

工作台在任务开始前拒绝暂停服务，运行中收到账户错误则保存失败、说明原因并阻止下一次发送。原Agent、工具、提示、评分、价格卡和费用结算没有修改。480元项目硬上限仍由原业务账本执行。

## 取舍

暂停按供应商而非单一模型共享，适合账号级余额/认证故障；不适合把普通模型无权访问误认成全账号故障，因此403只匹配明确余额信息。请求前检查不能撤销已在途调用，也不宣称故障后绝对零额外并发请求。SQLite开销计入端到端耗时，四实验配置共同使用。

## 验证

免费检查覆盖重建对象后暂停仍生效、其他供应商不受影响、发送/预留前拦截、首个错误保留、队列未开始任务不触发、并发在途请求结束后禁止下一次发送。另验证默认服装工作台确实注入包装客户端且保存用户可读失败说明。真实恢复探测仅一次，费用0.0000688元，与任何性能评测分母分开。

证据：`evidence/provider_gate_and_report_tests_20260908.xml`、`evidence/apparel_provider_jobs_tests_20260908.xml`、`evidence/aihubmix_recovery_probe_20260908.json`。原受故障影响的144次和新144次注册互相独立。
